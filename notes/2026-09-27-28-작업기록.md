## 1. MaaS — "maas-api is not available" 에서 API 키 200 까지

Gen AI Studio에서 키를 만들려 하면 두 번 막혔습니다. 해결 과정은
[11-maas-데모.md](../11-maas-데모.md)에 ①~⑦로 정리했고 여기서는 흐름만 남깁니다.

| 증상 | 원인 | 해결 |
|---|---|---|
| `maas-api is not available` | 게이트웨이 없음 → AuthConfig CRD 없음(RHCL 미설치) → DB 시크릿 없음 → 외부 호스트명·허용 네임스페이스 없음 | 게이트웨이·RHCL·PostgreSQL 준비, 게이트웨이 설정 |
| `No subscriptions available` | 구독은 모델이 1개 이상 있어야 함. MaaS는 `LLMInferenceService`만 등록 가능 | 32B를 LLMInferenceService로 전환(다운타임 5분), 모델 등록·구독·인증 정책 |
| 키로 불러도 401 | KServe가 게이트웨이에 자동으로 붙이는 인증 정책이 MaaS 정책을 덮어씀 | 같은 이름의 **자리표시자**로 교체(삭제하면 재생성됨) |
| 키로 불러도 403 | Authorino가 maas-api의 서비스 CA 인증서를 신뢰하지 않음(`tls: bad certificate`) | Authorino CR에 서비스 CA 마운트 |

최종: 키 있음 200 · 잘못된 키 403 · 폐기한 키 403 · 키 없음 401.

## 3. EvalHub 가 LLMInferenceService 를 못 재던 문제

### 증상

32B를 LLMInferenceService로 옮긴 뒤 같은 벤치마크를 돌리니 실패했습니다.

```
x509: certificate signed by unknown authority        (사이드카, 23,766건)
RuntimeError: Invalid rates in sweep; aborting.      (GuideLLM)
```

### 처음 세운 가설과 틀린 부분

"인증서가 KServe 자체 서명이라 서비스 CA로는 못 믿는다"고 추정했습니다. 시크릿 이름이
`qwen3-32b-awq-kserve-self-signed-certs`였기 때문입니다. **인증서를 직접 열어 보니 틀렸습니다.**

```
subject= /O=Kserve CA Signed
issuer=  /CN=openshift-service-serving-signer@…      ← 서비스 CA
SAN:     …-kserve-workload-svc.<PROJECT>.svc.cluster.local, …
```

인증서는 정상이고, 문제는 **사이드카의 모델 클라이언트가 서비스 CA를 읽지 않는 것**입니다.
사이드카 설정에는 `eval_hub.ca_cert_path`·`mlflow.ca_cert_path`가 있는데 `model`에는 `url`만
있었습니다.

### 막다른 길

| 시도 | 결과 |
|---|---|
| EvalHub API `model`에 TLS 필드 | 스키마에 없음 (`url`, `name`, `parameters`, `auth`) |
| 사이드카에 `SSL_CERT_DIR` 환경변수 | 사이드카 컨테이너 설정은 `image`·`resources`만 받음 |
| `evalhub-config` ConfigMap 수정 | EvalHub CR이 소유 — 오퍼레이터가 되돌림 |
| EvalHub CR에 사이드카 옵션 | 없음 (`env`는 API 서버용) |

### 답은 소스에 있었습니다

EvalHub는 오픈소스(`eval-hub/eval-hub`)입니다. 사이드카의 모델 클라이언트 생성 코드
(`internal/eval_runtime_sidecar/proxy/http_client.go`, `NewModelHTTPClient`)가 이렇습니다.

- `model.auth.secret_ref`로 넘긴 시크릿을 `/var/run/secrets/model`에 마운트한다
- 그 안에 **`ca_cert` 파일이 있으면** 모델 TLS의 RootCAs로 쓴다
- 없으면 "Model CA cert absent in secret mount, using system roots"

설치된 3.5.1 사이드카 바이너리에 같은 로그 문자열이 있는지 확인하고 적용했습니다.
**인증 시크릿이 CA를 싣는 통로를 겸합니다.** API 문서만 봐서는 알 수 없습니다.

```bash
scripts/19-evalhub-model-ca.sh        # ca_cert 키만 담은 시크릿
scripts/12-evalhub-benchmark.sh       # 기본값이 이제 LLMInferenceService URL + 이 시크릿
```

사이드카 로그: `Loaded CA certificate label=Model path=/var/run/secrets/model/ca_cert`, x509 0건.

### 결과

| 서빙 방식 | 출력 tok/s | TTFT ms | ITL ms |
|---|---|---|---|
| InferenceService (평문 8080), 4회 평균 | 36.88 | 105.1 | 26.5 |
| **LLMInferenceService (TLS 8000)** | **36.86** | **107.34** | **26.52** |

처리량은 같고 첫 토큰 지연이 약 2% 늘었습니다. MLflow run `096ffd28`로 기록했습니다.
실패했던 run은 결과로 오인되지 않게 삭제 처리했습니다.

> 인증서 검증을 끄는 `insecure_skip_verify`도 코드에 있지만 쓰지 않았습니다. 평가 도구가
> 검증을 끄면, 그 도구가 잰 모델이 정말 그 모델인지 보장할 수 없습니다.

## 4. 금융위원회 보고 양식 평가 보고서

금융위원회가 2026-06-22부터 시행한 「금융분야 AI 가이드라인」 개정판(7대 원칙)을 목차로 삼고,
금감원 AI RMF(거버넌스·위험평가·위험통제)와 금융보안원 평가체계(신뢰성 4·안전성 6)를

→ [16-금융위원회-보고-모델-평가-보고서.md](../16-금융위원회-보고-모델-평가-보고서.md)

- **사고를 숨기지 않습니다.** 7분 무인증 노출을 원인·영향·재발 방지로 적었습니다.
- **garak 수치는 인용하지 않습니다.** 공개 데이터가 예비값입니다.

## 5. 아직 확인하지 않은 것

- MaaS 사용량 화면에 숫자가 실제로 뜨는지, 한도 초과 시 429
- 검증 파이프라인을 LLMInferenceService 기준(`BASELINE=manifests/77-…`)으로 다시 돌리기
  — 코드는 고쳤지만 실행하지 않았습니다. 돌리면 32B가 30분 이상 내려갑니다.
- 파이프라인 `measure` 단계는 아직 CA 시크릿을 넘기지 않습니다. LLMInferenceService 후보를
  재려면 3장의 `auth.secret_ref`를 추가해야 합니다.
